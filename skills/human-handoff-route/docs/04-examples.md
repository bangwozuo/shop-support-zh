# 使用示例

以下示例的输入均为**真实可跑数据**，脚本输出由 `scripts/handoff_route.py` 实跑产生，非手写。

---

## 示例 1：售后会话批量分流（10 会话）

**输入**（`examples/input.json` 节选）：

```json
{
  "conversations": [
    {"会话ID": "C-1005", "买家": "买家E", "订单金额": 399,
     "消息": [{"角色": "买家", "内容": "我要退款，这个耳机左耳没声音，太差了，再不处理我就投诉到12315！"}]}
  ]
}
```

**命令**：

```bash
python3 scripts/handoff_route.py --input examples/input.json --outdir out
```

**输出**（实跑，10 会话：一线 5 / 二线 2 / 三线 3）：

| 会话ID | 主分类 | 情绪等级 | 升级信号 | 分流层级 | 接管时限 |
|---|---|---|---|---|---|
| C-1001 | 物流 | L1 轻微不满 | — | 一线自助 | AI/自助即时 |
| C-1002 | 质量 | L2 明显不满 | — | 二线人工 | < 3 分钟 |
| C-1004 | 发票 | L0 中性 | — | 一线自助 | AI/自助即时 |
| C-1005 | 退换货 | L3 愤怒 | 投诉、12315 | 三线（主管） | < 3 分钟 |
| C-1007 | 其他 | L4 极端/威胁 | 差评、曝光 | 三线（主管） | < 3 分钟 |
| C-1010 | 质量 | L3 愤怒 | — | 三线（主管） | < 3 分钟 |

**整改前**：原示例把 `items` 当占位符，输出「示例条目 A/B → 信息不完整」，等于没分流。
**整改后**：按分类树 + 情绪 + 升级信号三层判定，产出可派的工单台账。

## 示例 2：升级信号强制升三线

**输入**：

```json
{
  "conversations": [
    {"会话ID": "C-2001", "买家": "买家X",
     "消息": [{"角色": "买家", "内容": "东西一般，但我已经考虑找平台介入了"}]}
  ]
}
```

**输出**（实跑）：

| 会话ID | 主分类 | 情绪等级 | 升级信号 | 分流层级 |
|---|---|---|---|---|
| C-2001 | 其他 | L0 中性 | 平台介入 | 三线（主管） |

**要点**：即使情绪是 L0、分类是「其他」，只要命中「平台介入」就必须升三线 —— 这是
prompt.txt 的硬规则（升级信号优先于情绪与分类）。原逻辑完全没有这一层。

## 示例 3：一线可直接自助（不占用人工）

**输入**：

```json
{
  "conversations": [
    {"会话ID": "C-3001", "买家": "买家Y",
     "消息": [{"角色": "买家", "内容": "能开发票吗，需要专用发票报销"}]}
  ]
}
```

**输出**：主分类「发票」，情绪 L0，分流层级 **一线自助**（首响 < 30 秒，即刻答复）。

**价值**：把 FAQ 类咨询挡在人工之外。示例 1 中 10 通话里有 5 通被一线自助接住，
人工只处理需判断的质量/退换货/价格类，人工介入占比降到 50%。

## 示例 4：无输入对照组（--demo）

`python3 scripts/handoff_route.py --demo` 用内置 10 通话样例跑通全链路，产出
`out/分流台账.xlsx`、`out/分流层级分布.png`、`out/handoff.json`，无需准备数据。
