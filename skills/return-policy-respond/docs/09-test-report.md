## 二、示例实跑（提示词执行）

T2 为生成型资产，无脚本；验证方式为把 `prompt.txt` 全量作为系统提示词后对
`examples/input.json` 执行，人工审读输出。

**输入**：质量问题退货运费归属（见 `examples/input.json`）
**输出**：见 `examples/output.md`

| 项 | 结果 |
|---|---|
| 判定顺序 | 时限（第 5 天 ≤ 7 天）→ 例外（质量问题不受限）→ 运费 → 到账 ✅ |
| 运费责任判定 | 质量问题 → **店铺承担**（正确） |
| 四段结构完整 | ✅（共情/诊断/方案/行动） |
| 违规表述 | 无「概不退换」「一经售出概不负责」；无站外退款；无诱导删差评 |
| 越权承诺 | 未承诺政策外赔付；到账口径 1–3 个工作日符合事实 |

### 多维自检

| 维度 | 证据 |
|---|---|
| D1 领域术语 | 7 天无理由、《消法》第 25 条、无理由例外、三包、运费险、退货宝 |
| D2 具体阈值 | 7 天 / 1–3 个工作日 / 回复 ≤180 字 / 平台差异表 |
| D3 方法/算法 | 三步判定顺序 + 运费责任判定表 + 四段话术 |
| D4 领域边界 | 不用「概不退换」、不引导站外退款、例外商品仍保留质量通道 |
| D5 可交付输出 | 话术 + 政策判定表 + 升级判断表，含 `reply`/`policy`/`escalate` |

## 三、边界与已知限制

| 限制 | 说明 |
|---|---|
| 无脚本 | 时限/运费判定依赖 `context` 提供的签收时间与类目；缺参时先追问（已写进 prompt） |
| 平台规则时效 | 各平台无理由时长与价保会调整，以订单页/售后卡为准 |
| 类目差异 | 特殊类目（生鲜、定制、虚拟）判定复杂，超授权已要求转售后专员 |

## 四、结论

**通过。** 结构合规、prompt 深度达标；示例输出判定顺序正确、运费归属准确、零违规表述，信息不足场景能主动追问。
