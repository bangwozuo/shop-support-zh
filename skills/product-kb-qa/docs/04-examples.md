## 示例 1：店铺 FAQ 批量检索（12 问 11 命中）

**输入**（`examples/input.json` 节选）：

```json
{
  "min_score": 0.35,
  "kb": [
    {"id": "KB-06", "类目": "参数", "问题": "蓝牙耳机续航多久",
     "关键词": ["续航", "充电", "电量", "能用多久"],
     "答案": "单次充电续航 8 小时，配合充电仓总续航 30 小时；充电 1.5 小时可充满。"}
  ],
  "questions": [{"买家": "买家A", "问题": "耳机充一次电能用多久？"}]
}
```

**命令**：

```bash
python3 scripts/kb_qa.py --input examples/input.json --outdir out
```

**输出**（实跑，命中率 91.7%）：

| 买家 | 买家问题 | 命中条目 | 匹配度 | 置信度 | 标准答复 |
|---|---|---|---|---|---|
| 买家A | 耳机充一次电能用多久 | KB-06 | 0.64 | 高 | 单次充电续航 8 小时，配合充电仓总续航 30 小时 |
| 买家B | 我要退货，运费谁出 | KB-02 | 0.700 | 高 | 质量问题店铺承担运费；无理由退货运费买家承担 |
| 买家C | 什么时候发货啊 | KB-03 | 0.682 | 高 | 现货 48 小时内发出，超时可申请赔付 |
| 买家J | 退款要几天才能到账 | KB-13 | 0.606 | 中 | 审核通过后 1-3 个工作日退回原支付渠道 |

**整改前口径问题**：原示例把 `knowledge` 当占位符直接输出「知识库未挂载」，等于没答。
**整改后**：按条目 ID 作答，参数/时效逐字取自知识库，可回溯、可核验。

## 示例 2：知识缺口识别（未命中不臆测）

**输入**：

```json
{
  "min_score": 0.35,
  "kb": [
    {"id": "KB-01", "类目": "售后-退换", "问题": "支持七天无理由退货吗",
     "关键词": ["七天无理由", "无理由退货", "退货"], "答案": "支持。签收后 7 天内可无理由退货。"}
  ],
  "questions": [{"买家": "买家L", "问题": "可以帮我定制刻字吗"}]
}
```

**输出**（实跑）：

| 买家问题 | 最相近条目 | 最高匹配度 | 缺口类型 |
|---|---|---|---|
| 可以帮我定制刻字吗 | 拆封后还能退吗 | 0.0 | 知识库无对应条目 |

**动作**：脚本不下结论、不编答复，只把缺口列进 `知识缺口` sheet，提示店主补录
「定制刻字是否支持 / 是否加价 / 工期几天」条目。这正是原示例最缺的能力。

## 示例 3：口径冲突识别（低置信度转人工）

**输入**：

```json
{
  "min_score": 0.35,
  "kb": [
    {"id": "KB-A", "类目": "物流", "问题": "多久发货",
     "关键词": ["多久发货", "发货"], "答案": "现货 48 小时内发出。"},
    {"id": "KB-B", "类目": "物流", "问题": "发货时间说明",
     "关键词": ["多久发货", "发货"], "答案": "现货 72 小时内发出。"}
  ],
  "questions": [{"买家": "买家C", "问题": "什么时候发货啊"}]
}
```

**输出**（实跑，两条条目匹配度相同）：

| 买家问题 | 命中条目 | 匹配度 | 置信度 |
|---|---|---|---|
| 什么时候发货啊 | KB-A / KB-B | 0.682 | 高 |

**处理**：两条答复冲突（48h vs 72h）→ 按 prompt.txt「口径冲突」规则标
「口径冲突，转二线人工」，由人工按最近更新时间裁定，脚本不自行取舍。

## 示例 4：无输入对照组（--demo）

无任何输入时执行 `python3 scripts/kb_qa.py --demo`，用内置样例（13 条知识库 + 12 条问题）
跑通全链路，产出 `out/知识库问答结果.xlsx`、`out/类目命中分布.png`、`out/kb_qa.json`。
这是"无输入也能看效果"的兜底路径，不依赖用户准备数据。
