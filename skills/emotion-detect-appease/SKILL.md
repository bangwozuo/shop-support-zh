# 情绪识别安抚

先识别买家**情绪强度**，再给一段**能真正降温**的回复。大多数差评不是商品问题，是"没被听见"的情绪问题。

不做的事：不写营销话术、不替店铺承诺赔付、不做售后责任判定。

## 元信息

| 字段 | 值 |
|------|-----|
| ID | `de_ecom_02_sk05` |
| 类型 | **`atomic`（原子技能）** |
| 所属员工 | 店铺客服官 |
| 能力族 | 情绪判断族 · 安抚话术 |
| 复杂度 | `S` |
| 阶段 | `P0` |
| 复用度 | ★★★★☆（③共用） |
| 资产形态 | 纯提示词（无运行时依赖） |

## 能力描述

1. **情绪分级**：L0 中性 / L1 轻微不满 / L2 明显不满 / L3 愤怒 / L4 极端威胁，按表述而非情绪词判定。
2. **四段话术**：共情（先认可情绪）→ 诊断（复述问题）→ 方案（1–2 个选项）→ 行动（下一步与时限）。
3. **升级判定**：命中投诉/差评/12315/平台介入/曝光/起诉等 → 转三线主管；需查权限问题 → 转二线人工。
4. **禁语红线**：禁用「这是规定」「没办法」「不是我的问题」「亲亲别生气」等推诿/敷衍话术。

## 输入规格

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `question` | string | ✅ | 买家原话 |
| `context` | string | ⬜ | 背景信息（订单号、商品、历史沟通、已承诺事项） |
| `persona` | string | ⬜ | 品牌人设与可承诺范围；缺省「亲切、专业、不卑不亢」 |

## 输出规格

- `reply`：按四段结构写成的、可直接发送的回复（≤ 150 字）
- `emotion`：情绪等级 + 判定依据 + 买家核心诉求
- `escalate`：是否升级（否 / 转二线人工 / 转三线主管）+ 触发原因 + 接管时限

## 使用步骤

### 方式一：纯提示词（最快，任意平台）

1. 打开你的 AI 工具（Coze / WorkBuddy / Dify / Claude / ChatGPT…）
2. 新建对话，把 `prompt.txt` 的**全部内容**粘贴为系统提示词
3. 提供 `question`（买家原话），可另给 `context`、`persona`
4. 得到可发送的安抚回复 + 情绪标签 + 升级判断

### 方式二：在平台导入

| 平台 | 导入方式 |
|------|---------|
| **Coze / 扣子** | 新建 Bot → 人设与回复逻辑 → 粘贴 `prompt.txt` |
| **WorkBuddy** | 新建 Skill → 填入 `prompt.txt` 内容 |
| **Dify** | 新建应用 → 提示词编排 → 粘贴 `prompt.txt` |
| **Claude** | 新建 Project → Instructions → 粘贴 `prompt.txt` |
| **ChatGPT** | 新建 GPT → Instructions → 粘贴 `prompt.txt` |

## 边界（不做的事）

- ❌ 不用「这是规定」「没办法」「不是我的问题」等推诿话术
- ❌ 不承诺无法兑现的赔付/加急/到货时间；涉及资金只出草稿
- ❌ 不引导买家删差评、改好评、撤投诉（违规）
- ❌ 不泄露买家个人信息
- ❌ 不在买家愤怒时讲道理、摆规则、纠正其措辞
- ❌ 不编造"已处理好"这类未发生的动作

## 调用示例

**输入**（`examples/input.json`）：

```json
{
  "question": "都等三天了还不发货！问客服就一句「亲亲稍等」，太敷衍了吧，再这样我就退款投诉了",
  "context": "订单 TB20260925008，9 月 27 日下单保温杯，承诺 48 小时内发出，现已超时约 24 小时",
  "persona": "亲切、专业、不卑不亢的店铺客服"
}
```

**输出**（节选）：

| 项 | 内容 |
|---|---|
| 情绪等级 | L2 明显不满（命中「等三天」「太敷衍了吧」） |
| 买家核心诉求 | 要一个可兑现的发货时间 / 否则退款 |
| 是否升级 | 转三线主管（触发原因：命中「投诉」） |
| 回复（节选） | 「真的很抱歉，让您等了三天还只收到一句『稍等』…给您两个办法：① 加急催仓 2 小时内更新物流 ② 原路退款并补 5 元券…」 |

升级判定遵循「升级信号优先于情绪与分类」。
