## 二、示例实跑（提示词执行）

T2 为生成型资产，无脚本；验证方式为把 `prompt.txt` 全量作为系统提示词后对
`examples/input.json` 执行，人工审读输出。

**输入**：超时未发货 + 威胁投诉（见 `examples/input.json`）
**输出**：见 `examples/output.md`

| 项 | 结果 |
|---|---|
| 情绪分级 | L2 明显不满（命中「等三天」「太敷衍了吧」） |
| 四段结构完整（共情/诊断/方案/行动） | ✅（4/4 段齐全） |
| 禁语命中（这是规定/没办法/不是我的问题/亲亲别生气） | 0 |
| 方案数量 | 2 个（符合「1–2 个」约束） |
| 升级判定 | 转三线主管（命中「投诉」，符合"升级信号优先"硬规则） |
| 越权承诺（超出 24h / 未经授权的赔付金额） | 0 |

### 多维自检

| 维度 | 证据 |
|---|---|
| D1 领域术语 | 情绪分级 L0–L4、四段话术结构、升级触发信号、首响/接管 SLA |
| D2 具体阈值 | 首响 <30 秒、接管 <3 分钟、售后 24 小时、回复 ≤150 字、方案 1–2 个 |
| D3 方法/算法 | 分级表 + 四段结构 + 升级判定顺序（信号 > 情绪 > 分类） |
| D4 领域边界 | 禁语表、不引导删差评/撤投诉、不越权承诺、不在愤怒时讲道理 |
| D5 可交付输出 | 回复 + 情绪表 + 升级判断表，含 `reply`/`emotion`/`escalate` |

## 三、边界与已知限制

| 限制 | 说明 |
|---|---|
| 无脚本 | 本资产为纯提示词，无确定性数值计算；情绪判定依赖模型理解，建议关键场景人工复核 |
| 情绪词表非穷尽 | 方言、网络新词可能影响分级；prompt 已要求"看表述不看情绪词" |
| 升级从严 | 命中「投诉」即升三线，可能增加主管工作量，换取的是纠纷零遗漏 |

## 四、结论

**通过。** 结构合规、prompt 深度达标；示例输出四段结构齐全、零禁语、零越权承诺，升级判定符合硬规则。
