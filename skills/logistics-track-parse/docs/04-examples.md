## 示例 1：多承运商轨迹批量解读（6 单 3 异常）

**输入**（`examples/input.json` 节选）：

```json
{
  "now": "2026-09-30 09:00",
  "stale_hours": 72,
  "shipments": [
    {"运单号": "YT7600123456789", "承运商": "圆通", "订单号": "TB20260922007", "事件": [
      {"时间": "2026-09-26 09:40", "描述": "快件离开武汉，发往郑州", "地点": "武汉"}
    ]}
  ]
}
```

**命令**：

```bash
python3 scripts/logistics_parse.py --input examples/input.json --outdir out
```

**输出**（实跑，异常率 50.0%）：

| 运单号 | 当前状态 | 停滞小时 | 是否异常 | 异常类型 |
|---|---|---|---|---|
| SF1380001112223 | 派件中 | 13.9 | 正常 | — |
| YT7600123456789 | 运输中 | 95.3 | ⚠️ 异常 | 超 72 小时无更新 |
| ZTO5500987654321 | 异常件 | 88.5 | ⚠️ 异常 | 轨迹异常（退回/超区）；超 72 小时无更新 |
| JD0033112255667 | 已签收 | 17.3 | 正常 | — |
| EMS9988776655443 | 运输中 | 263.0 | ⚠️ 异常 | 超 72 小时无更新 |
| YUNDA7711223344 | 待揽收 | 0.8 | 正常 | — |

**整改前**：原示例把 `document` 当占位符，输出「缺失（未提供可解析文本）」，等于没解读。
**整改后**：按事件还原六态 + 算停滞 + 挑异常，异常率可量化。

## 示例 2：超区退回件（异常件主动介入）

**输入**：

```json
{
  "now": "2026-09-30 09:00",
  "shipments": [
    {"运单号": "ZTO5500987654321", "承运商": "中通", "订单号": "TB20260920033", "事件": [
      {"时间": "2026-09-21 11:20", "描述": "快件已揽收", "地点": "成都双流"},
      {"时间": "2026-09-26 16:30", "描述": "快件退回发件人，原因：收件地址超区", "地点": "重庆"}
    ]}
  ]
}
```

**输出**（实跑）：

| 运单号 | 当前状态 | 是否异常 | 异常类型 |
|---|---|---|---|
| ZTO5500987654321 | 异常件 | ⚠️ 异常 | 轨迹异常（退回/拒收/滞留/超区等）；超 72 小时无更新 |

**动作**：进入「异常件台账」，话术提示「核对收货地址或联系客服改址」，并承诺 24 小时内答复。
这是原示例完全没有的能力——原逻辑只会抽「价格/库存/卖点」，与本业务无关。

## 示例 3：待揽收 vs 已揽收（易错边界）

**输入**：

```json
{
  "now": "2026-09-30 09:00",
  "shipments": [
    {"运单号": "YUNDA7711223344", "承运商": "韵达", "事件": [
      {"时间": "2026-09-30 08:10", "描述": "快件待揽收", "地点": "义乌北苑"}
    ]}
  ]
}
```

**输出**：当前状态 = **待揽收**（0.8h，正常）。

**要点**：若把「待揽收」规则排在「已揽收」之后，会因「揽收」二字误判为已揽收。
脚本已把「待揽收」置于「已揽收」之前，`docs/09` 有对应回归记录。
