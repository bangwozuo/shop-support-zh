# 使用示例

以下示例的输入均为**真实可跑数据**，输出为把 `prompt.txt` 全量作为系统提示词后的应答结果。

---

## 示例 1：比价 + 压价（守住底线）

**输入**（`examples/input.json`）：

```json
{
  "question": "老板这个耳机199太贵了吧，隔壁家同款才159，便宜点我马上拍",
  "context": "无线降噪耳机，标价 199，成本 120，最低毛利率 25%（底线 150）；活动满 199 减 20；竞品 159 为无降噪老版本",
  "persona": "一线客服，可自主用券/赠品/包邮，直接让价上限 5%"
}
```

**输出**：

| 项 | 内容 |
|---|---|
| 议价类型 | 比价型 + 压价型 |
| 价值锚点 | 主动降噪 vs 竞品无降噪；一年联保；赠收纳盒 |
| 让步档位 | 满 199 减 20 + 5 元券 + 赠品 + 包邮，实付 174 |
| 底线校核 | 底线 150 元；成交 174 > 150 ✅ |
| 五段回复（节选） | 「理解的，谁都想买得更划算～不过隔壁 159 那款是无降噪的老版本…这样给您：① 满 199 减 20 到手 179 ② 再叠 5 元券最低 174 还送收纳盒…」 |

**整改前**：原示例对「这个多少钱」只回「去看详情页」，没有类型识别、没有底线、没有让步档位。
**整改后**：类型识别 + 底线价校核 + 授权档位让步，可落地、可审计。

## 示例 2：威胁型（不追着降价）

**输入**：

```json
{
  "question": "就这个价？不便宜我就去别家买了",
  "context": "保温杯 89 元，成本 45，最低毛利率 20%（底线 54）；无额外活动",
  "persona": "一线客服，可自主赠品 1 件，无让价授权"
}
```

**输出**：

| 项 | 内容 |
|---|---|
| 议价类型 | 威胁型 |
| 应对主轴 | 不追价；给一次性最优案 + 体面台阶 |
| 让步档位 | 送杯刷 1 件 + 包邮（不降价，未击穿底线 54） |
| 回复（节选） | 「理解您想更划算～这个价确实做实了，我能做的是送您一支原装杯刷、包邮，凑单满 99 还能再减 5…您再考虑下，随时喊我～」 |

**要点**：威胁型**绝不追着降价**，避免被"再等等还能更低"套牢。

## 示例 3：价保型（符合即补，不符合给替代）

**输入**：

```json
{
  "question": "我上周买的，今天怎么便宜了20，能补差价吗",
  "context": "订单 9 月 24 日成交 199 元，现价 179 元；淘宝普通商品价保期 15 天；降价为店铺直降",
  "persona": "一线客服，可自主引导平台价保入口"
}
```

**输出**：

| 项 | 内容 |
|---|---|
| 议价类型 | 价保型 |
| 规则校核 | 成交 9-24，距今 6 天 ≤ 15 天，且在保 → 符合价保 |
| 动作 | 引导走「订单页 → 申请价保」入口补差 20 元（**不私下补现金**） |

**要点**：符合价保就走平台入口，不符合（超期/仅大促期）则说明规则并给替代（券/赠品）。

---

## 示例 4：无 context 时（不报底价）

未提供成本/底线时，一律**不报"最低价"**，只回「我去帮您申请一下更优方案」；
避免报出击穿底线的价格或承诺无法兑现的优惠。
